# MeetMate · AI 组局推荐

把群聊粘进去，自动读出「谁要什么、谁从哪出发」，实时检索高德真实商户，算通勤时间和花费，
逐条核对每个人的要求，选出一家**能说清为什么选它**的店；资料查不清的店只进备选。

## 它到底做了什么

1. **读懂群聊**：按「谁说了什么」切分行（支持微信复制、`名字 19:23`、`[19:23] 名字`、手打 `名字 内容` 等排版），
   逐条抠出要求并标注提出者、强度（`hard` 不能让步 / `strong` 强烈希望 / `soft` 随便）、原话。
1.5 **判断城市**：从地名、商圈、地铁线路名推断（「春熙路」→ 成都、「陆家嘴」→ 上海），
   推断不出来再用 12 个城市的地标词表兜底；城市会跟着方案一起存下来，
   之后改位置、追问、重新排序都沿用，不会退回默认城市。
2. **落每个人的位置**：原话里抓地名优先（「我从三墩出发」），AI 的解读兜底，
   再交给高德 POI 检索定位（口语地名如「转塘」「良渚」「钱江新城」都能解析）。
   读不到的人不画点、不画线、不参与锚点计算，不会拿假坐标凑数。
3. **搜真店**：以「成员几何中心 + 离中心最远的那个人」双锚点检索，不和某个固定出发点绑定。
4. **算两条路**：每个成员同时算驾车和地铁/公交，按「时间 × 时间价值 + 票钱」取更划算的那个。
5. **逐条核对**：预算→人均、距离→耗时、室内外/类型→场所关键词，能算的用数据算；
   语义类要求（「怕黑」「别太吵」）交给 AI 判，只允许判 `pass / conflict / unknown`，资料不足必须说 unknown。
6. **定首选 + 备选**：硬性要求被违背的直接排除；资料查不清（关键要求 `unknown`）的店只进备选；
   首选从「资料能说清」的店里出，AI 选错会按核对结果改选并说明原因。

## 快速开始

需要 Node.js 20+。

```bash
npm install
cp .env.example .env.local   # 填 AMAP_WEB_KEY
npm run dev                  # http://localhost:3000
```

城市不用选：城市跟着群聊里的地名走。想换城市，直接粘那个城市的群聊即可。

### 两个 Key

| Key | 用途 | 放哪 |
| --- | --- | --- |
| `AMAP_WEB_KEY` | 高德 **Web 服务** 类型 Key，检索商户、算路线 | `.env.local`（服务端） |
| AI Key（DeepSeek） | 读群聊、判语义要求 | 页面左下角「设置」里填，存 localStorage；也可在 `.env.local` 配 `DEEPSEEK_API_KEY` 让所有人共用 |

Key 只在服务端转发使用，不会打进前端产物。

## 目录结构

```
src/
  app/
    page.tsx                     首页：粘贴群聊 → 生成方案
    room/[id]/                   房间页：地图、首选、备选、成员、需求核对
    room/[id]/chat/              追问与改方案
    room/[id]/activity/          活动详情
    api/
      extract/                   群聊 → 成员 / 需求 / 关键词
      plan/                      检索 + 测距 + 打分 + 决策
      reroute/                   只改成员位置时重算
      chat/                      追问（换一家、加条件）
      geocode/ places/           地名解析与候选地点
      health/                    部署自检：只回报有没有读到 Key
  lib/
    planner.ts                   核心：抽取、成员定位、打分、决策、路线
    place.ts                     口语地名 → 坐标（POI 检索 + 相似度/类型加权 + 地理编码兜底）
    amap.ts                      高德接口封装（多锚点检索、驾车、公交地铁、缓存）
    meetmate.ts                  共享类型
    ai.ts                        DeepSeek 调用
  components/
    tile-map.tsx                 高德栅格瓦片地图（推荐点 / 成员点 / 路线）
    settings-panel.tsx           左下角 Key 设置（存 localStorage）
    illustrations.tsx            全内联 SVG 插画
    icons.tsx / site-header.tsx  图标与顶栏
```

## 部署

三处都要配两个环境变量（`.env.local` 已被 `.gitignore` 忽略，不会进仓库）：

| 变量 | 说明 |
| --- | --- |
| `AMAP_WEB_KEY` | 高德 **Web 服务** Key，没有它拿不到任何真实地点 |
| `DEEPSEEK_API_KEY` | 可选。不配也能用，让每个访问者在页面左下角填自己的 Key |

**Netlify**（仓库里已带 `netlify.toml`：构建 `npm run build`、发布 `.next`、Node 22）

1. 导入仓库，不用改构建配置；
2. Site configuration → Environment variables 加上面两个变量，**作用域勾上 Functions**；
3. 改完必须重新 deploy 才生效；
4. 打开 `https://<站点>/api/health` 自检：`hasAIKey` / `hasAmapKey` 都是 true 才算配好。
   这个接口只回报「有没有读到」，不会回显 Key，还会列出匹配 `AMAP|DEEPSEEK|API_KEY` 的变量名，
   变量名打错（比如写成 `AMAP_KEY`）一眼就能看见。

> **时间约束**：Netlify 同步函数有硬超时。实测海外节点调高德单次 1-2 秒，
> 一次完整分析约 12-16 秒。代码里做了三层兜底：8 秒后不再补地铁查询、
> 决策超时就退回评分排序、前端遇到 502 会用 fast 模式再试一次（约 5 秒出结果）。
> 想彻底去掉这个约束，可以换 Vercel（Hobby 默认 60 秒），或升级 Netlify 提工单把超时调到 26 秒。

**Vercel**：导入仓库 → 填环境变量 → 部署，无需额外配置。

**自建服务器 / 容器**：`npm ci && npm run build && npm start`，进程需监听 `PORT` 并绑定 `0.0.0.0`。

## 已知限制

- **通勤时间依赖高德实时接口**：地铁方案有时会抖动（同一段路两次查出来差几分钟），
  所以排序里地铁和打车是各算一次再取更划算的；查不到的人标「算不出」，不会编数字。
- **语义类要求只能判到 unknown**：有没有包间、吵不吵、卫生怎么样，商户数据里没有，
  系统会明写「需到店确认」，不会替商家打包票。
- **出发地必须说出口**：群聊里没提自己在哪的人，不画点、不画线、不参与锚点计算。
- **线上有超时**：免费版 Serverless 的函数时长限制见上一节。
